# SakikoMind 五分钟演示脚本

## 演示前检查

1. 启动后端：`docker compose up -d`，确认五个服务健康。
2. 打开前端：`http://127.0.0.1:5173`。
3. 左侧状态应显示：服务健康为 `ok`、知识片段为 `25`、业务 Skills 为 `7`。
4. 如需展示底层接口，准备 `http://localhost:8000/docs`；如需展示指标，准备 `http://localhost:8000/metrics` 或 `http://localhost:9090`。

## 场景一：退款政策问答与 RAG 可追溯性

**目标：** 展示“不是裸聊”，而是带知识引用的客服回答。

1. 在“对话”工作区点击“退款政策”，确认输入框填入问题。
2. 点击“发送”。
3. 展示回复中的意图、Agent、`RAG` 标记，以及“参考资料”里的退款政策、`source_id` 和相关度。
4. 切换到“知识库”，搜索“退款多久到账”，展示命中文档。

**讲解：** “模型回答前会经过查询改写、并行召回、关键词加权与重排。回复同时回传来源摘要，所以客服结论可以追溯到具体政策。”

## 场景二：401 排障与 Skill 约束

**目标：** 展示多 Agent 路由与业务规范，不只展示回答文本。

1. 回到“对话”，点击“401 排障”，再发送。
2. 展示回复的 `technical` 意图与 Technical Agent。
3. 展示“生效规则”中的技术支持处理规范和命中关键词。
4. 讲解回复中的诊断顺序：错误信息、认证方式、网络、日志与可复现步骤。

**讲解：** “意图识别决定路由，Skill 决定该 Agent 能问什么、承诺什么、什么时候升级。Skill 是可热更新的 Markdown 业务规范，不需要每次改代码或重训模型。”

## 场景三：高风险转人工与可观测闭环

**目标：** 展示高风险场景的受控升级、工单持久化和监控。

1. 在“对话”点击“高风险转人工”，发送。
2. 展示回复中的 `转人工` 标记、人工升级工单卡片、优先级和 Trace。
3. 切换到“工单”，展示同一工单已进入待办队列；可将状态改为“处理中”。
4. 切换到“监控”，点击“刷新全局状态”，展示 Agent 状态、工具统计、告警恢复和优化建议。
5. 打开 `/metrics`，说明 HTTP、`memory_read`、`rag`、`agent`、`memory_write` 与画像异步更新都有 Prometheus 指标。

**讲解：** “高风险升级不是只让模型说‘已转人工’，而是会创建持久化 SQLite 工单。Trace 把前端、日志、RAG、Agent 与工单串起来；查询改写和重排超时后会降级，避免单个模型调用卡住客服主链路。”

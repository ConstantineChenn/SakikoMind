# SakikoMind 云端部署指南

本指南将当前 Docker Compose 项目部署到 Linux 云服务器。部署后只有统一 Nginx 网关的 HTTP 入口公开：它同时提供 Sakiko Console 前端静态页和 SakikoMind API；Redis、ChromaDB、应用容器与 Prometheus 不直接暴露到公网。

## 1. 准备服务器

- 推荐 Ubuntu 22.04+、2 vCPU、4 GB 内存、40 GB 磁盘。
- 安装 Docker Engine 与 Docker Compose Plugin。
- 在云防火墙中仅放行 `22`、`80`，HTTPS 配置完成后再放行 `443`。
- 不要在安全组中放行 `6379`、`8000`、`8001`、`9090` 或 `9091`。

## 2. 上传项目与创建环境变量

上传包解压后，目录必须保持以下同级结构，因为网关镜像会从 `../SakikoMindFrontend/dist` 读取已构建的前端静态文件：

```text
/opt/sakikomind/
├── SakikoMind/
└── SakikoMindFrontend/
```

在服务器的 `/opt/sakikomind/SakikoMind` 目录执行：

```bash
cp .env.example .env
chmod 600 .env
openssl rand -base64 36
```

将生成的随机值写入 `REDIS_PASSWORD`，再填写 `ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL` 和 `ANTHROPIC_MODEL`。不要将真实密钥提交到 Git、截图或发送到聊天中。

同域网关下，前端会自动使用当前域名访问 API，`CORS_ALLOWED_ORIGINS` 可保留本地开发地址。只有将前端部署到独立域名时，才需加入该域名，例如：

```dotenv
CORS_ALLOWED_ORIGINS=https://app.example.com
```

若前端暂未上云，可临时包含本地开发地址；正式公开前必须移除通配符 `*`。

## 3. 启动生产编排

```bash
docker compose -f docker-compose.yml -f docker-compose.production.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.production.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.production.yml ps
curl -fsS http://127.0.0.1/health
```

`docker-compose.production.yml` 使用 Docker Compose v2.24+ 的 `!reset` 语法隐藏本地开发端口。公网仅由 Nginx 的 `80` 端口接收请求；Prometheus 绑定在服务器回环地址 `127.0.0.1:9090`，可通过 SSH 隧道查看：

```bash
ssh -L 9090:127.0.0.1:9090 user@your-server
```

然后在本机打开 `http://127.0.0.1:9090`。

## 4. 配置 HTTPS

生产环境必须在 Nginx 前配置 HTTPS。可选方案：

1. 云负载均衡或 CDN（例如 Cloudflare）终结 TLS，并回源到服务器 `80`。
2. 在同一服务器使用 Caddy 或 Certbot 为域名签发证书，再反向代理到 SakikoMind Nginx。

当前编排已将构建好的 Vue 前端打包进公网 Nginx 网关。访问 `http://你的域名或公网IP/` 即可打开 Sakiko Console；其左侧 API 地址默认就是当前域名，无需手动填写。独立部署前端时，才需要将其域名加入 `CORS_ALLOWED_ORIGINS`。

## 5. 上线验收与排障

1. `/health` 返回 `status: ok`。
2. `/skills` 可查看 7 个业务 Skills。
3. `/chat` 完成退款、401、重复扣款和转人工四类冒烟测试。
4. `/monitor` 与 `/metrics` 仅从内网、SSH 隧道或受控运维入口访问。
5. 使用 `docker compose -f docker-compose.yml -f docker-compose.production.yml logs -f sakikomind` 按 `trace_id` 检索单次请求。

部署前后均应备份 `data/handoffs`、`data/eval` 与 Docker volumes；不要把生产用户对话、工单或知识文档复制到公开仓库。
